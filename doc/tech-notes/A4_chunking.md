# 文档分块策略（Chunking）

## 是什么
Chunking 是把长文档切成适合检索的小片段的过程。块太大 → 噪声多、超出窗口、检索不精准；块太小 → 语义断裂、上下文丢失。分块质量直接决定 RAG 上限。

## 常见策略
- **定长切分**：每 N 个 token/字符一刀切，简单但容易切断语义（如把一段代码从中间劈开）。
- **递归字符切分（Recursive）**：按 `\n\n` → `\n` → 句号 的优先级递归切，尽量保留段落/句子边界，LangChain 默认即用此法。
- **语义切分**：用 embedding 相似度判断「该不该切」，相邻句相似度骤降处切，语义最连贯但成本高。
- **按结构切分**：Markdown 按标题层级、代码按函数/类切，最适合技术文档。

## 本项目怎么切
导入图里 `node_document_split` 负责切分。技术文档（MD）按标题层级 + 段落递归切，保留「所属章节」元数据，便于检索时带上上下文。

## 经验值
- 技术文档：单块 300–800 字较稳；
- 保留 overlap（块间重叠 10–20%）避免切断边界信息；
- 代码块别切碎，按函数整体保留。
