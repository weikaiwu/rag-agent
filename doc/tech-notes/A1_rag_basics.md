# RAG 基础流程（检索增强生成）

## 是什么
RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大语言模型（LLM）在回答时先去外部知识库检索相关片段、再把片段拼进 Prompt 一起生成答案的架构。它解决的是 LLM「知识固化在训练截止日之前」和「容易一本正经胡说（幻觉）」两个问题。

## 核心流程（三段式）
1. **检索（Retrieve）**：把用户问题向量化，去向量库里找最相似的若干文档片段（chunk）。
2. **增强（Augment）**：把检索到的片段拼接到系统提示词里，作为「已知上下文」。
3. **生成（Generate）**：LLM 基于「问题 + 检索上下文」产出最终答案，并尽量引用来源。

## 为什么不直接微调
- RAG 知识可随时更新（改向量库即可），微调要重新训练；
- RAG 答案可溯源，微调是「黑盒记忆」；
- 小团队成本上 RAG 远低于微调。

## 与本项目的关系
本项目就是一套完整的 RAG 管道：LangGraph 编排「确认主题 → 多路检索（Milvus 稠密+稀疏 / Web MCP / 知识图谱）→ 融合（RRF）→ 重排（BGE-reranker）→ 生成」。检索阶段还用了 HyDE（假设性文档嵌入）提升召回。

## 常见坑
- 检索到的片段和问题是「字面相似」而非「语义相关」→ 需要重排序兜底；
- 上下文塞太多导致超出窗口或引入噪声 → 动态 TopK + 噪声截断；
- 检索为空时 LLM 直接编 → 要加「无上下文」兜底逻辑。
