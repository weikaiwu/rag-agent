# Agent 推理模式：ReAct / Plan-and-Execute / Reflection

## 是什么
Agent 不是「一次生成就完事」，而是「推理—行动—观察」的循环。几种主流推理范式：

- **ReAct**（Reasoning + Acting）：交替进行「思考下一步 → 调工具 → 看结果 → 再思考」，最通用，适合需要边查边答的任务。
- **Plan-and-Execute**：先一次性规划完整步骤，再逐步执行。适合步骤明确、可并行的任务，但计划僵化、难应对意外。
- **Reflection（反思）**：生成答案后自我审查/纠错，再迭代。适合要求高正确率的场景。

## 对比
| 范式 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| ReAct | 灵活、可应对不确定 | 步数多、token 贵 | 开放问答、工具调用 |
| Plan-and-Execute | 结构清晰 | 计划易过时 | 流程固定任务 |
| Reflection | 质量高 | 慢、贵 | 代码/写作 |

## 与本项目的关系
本项目查询图本质是 ReAct 式编排：LangGraph 里「确认主题→多路检索→融合→重排→生成」就是「思考（确认产品/主题）→ 行动（检索工具）→ 观察（融合结果）→ 再行动（重排）→ 生成」。Web Search MCP 是典型「工具调用」环节。

## 趋势
2025 起多智能体常组合这些范式：规划 Agent 用 Plan，执行 Agent 用 ReAct，校验 Agent 用 Reflection。
