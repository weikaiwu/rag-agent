# Query 改写与 HyDE（假设性文档嵌入）

## 是什么
用户原问题常常口语化、缺上下文、或带指代（"它怎么配置"）。**Query 改写**把问题改写成检索友好的标准形式；**HyDE（Hypothetical Document Embeddings）** 让 LLM 先「编一个理想答案」，再用这个假答案的向量去检索——因为假答案的语义分布比原问题更接近真实文档。

## 为什么有用
- 原问题「这玩意儿咋连不上网」→ 改写「系统无法连接 WiFi 的排查步骤」检索更准；
- HyDE：问题「RAG 怎么评估」→ LLM 生成一段假答案 → 用假答案向量去 Milvus 找真文档，命中率常高于直接用短问题。

## 与本项目的关系
查询图里有 `node_search_embedding_hyde` 节点：先让 LLM 基于问题生成假设性文档，embedding 后用它检索；另有常规 embedding 检索做对照，两路在 RRF 融合。对应技术问答场景，HyDE 对「概念解释类」问题（如"什么是上下文工程"）提升明显。

## 注意
- HyDE 在「事实精确型」问题（含专有名词）上提升有限，纯稠密+稀疏可能更好；
- 改写要用轻量模型，别为改写下重模型拖慢整体。
