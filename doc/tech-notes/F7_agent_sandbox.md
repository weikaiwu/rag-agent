# Agent 沙箱与安全执行（Sandbox）

## 是什么
当 Agent 能「执行代码 / 跑命令 / 调外部系统」时，必须把它关在**沙箱（Sandbox）**里——隔离的运行环境，限制它能访问的文件、网络、算力，防止恶意或失控的操作搞坏主机或泄露数据。常见方案：Docker 容器、gVisor、Firecracker 微虚机、云端沙箱（如 E2B、Modal）。

## 为什么 Agent 特别需要
Agent 会「自主决定下一步动作」，若它能执行任意代码，一旦被诱导（prompt injection）就可能 `rm -rf`、外泄密钥。沙箱是最后一道防线。

## 主流方案
- **E2B**：专为 AI Agent 设计的代码执行沙箱，开箱即用；
- **Docker / 容器**：隔离进程和文件系统；
- **gVisor / Firecracker**：更硬核的内核级隔离；
- **本地 subprocess + 严格白名单**：轻量但不彻底。

## 与本项目的关系
本项目当前 Agent 只做「检索 + 生成」，不执行用户代码，风险面小。但若将来加「代码执行 Agent」（如让用户问『跑个 Python 片段』），就必须上沙箱。我在知识库把它作为安全演进方向记录。

## 注意
- 沙箱不是万能，prompt injection 仍要通过输入校验 + 输出过滤多层防御（见 F11）。
