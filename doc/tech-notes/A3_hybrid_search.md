# 混合检索（稠密 + 稀疏）

## 是什么
混合检索（Hybrid Search）同时用「稠密向量语义检索」和「稀疏向量/关键词检索」两路召回，再融合结果。单独用稠密检索会漏掉精确术语（如错误码 E12、型号名），单独用稀疏检索又不懂同义改写，混合检索取长补短。

## 为什么需要
- 用户问「系统报 E12 怎么处理」→ 稀疏检索能精准命中含 "E12" 的片段，稠密可能把它和别的报错混了；
- 用户问「电池很快就没电了」→ 稠密检索能命中「续航短」「电量消耗快」，稀疏检索未必。
两路互补，召回更全面。

## 融合方式
- **RRF（Reciprocal Rank Fusion）**：只按各路的排名融合，不依赖分数绝对值，鲁棒（本项目采用）；
- **加权求和**：把两路分数归一化后加权，需要调权重；
- **向量数据库原生融合**：Milvus 2.4+ 支持 `hybrid_search` 一次查多路并自动融合。

## 与本项目的关系
`node_search_embedding_hyde` / `node_search_embedding` 产出稠密+稀疏两路候选，`node_rrf` 用倒数排名融合去重排序。对应知识库是技术文档问答后，混合检索能同时抓住「技术术语精确匹配」和「概念语义匹配」。

## 注意点
- 两路分数量纲不同，不能直接相加，RRF 用排名更稳；
- 融合后仍需重排序精排，否则 TopK 里混着弱相关。
