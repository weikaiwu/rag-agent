# 微调 vs RAG（含 SFT / LoRA / DPO 浅述）

## 是什么
让 LLM「懂你的领域」有两条主流路：
- **RAG**：外挂知识库，回答时检索注入，不改模型权重（本项目采用）；
- **微调（Fine-tuning）**：用领域数据继续训练，改模型权重，把知识「烧进」参数。

微调常见方式：
- **SFT（监督微调）**：用「指令-回答」对训练；
- **LoRA / QLoRA**：只训低秩适配器，省显存、快、可插拔；
- **DPO**：直接用偏好数据对齐，不用单独训奖励模型。

## 怎么选
| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 改库即可 | 重训 |
| 可溯源 | 能引来源 | 黑盒 |
| 成本 | 低（不训） | 高（显卡/数据） |
| 改「风格/格式」 | 弱 | 强 |
| 改「事实知识」 | 强 | 中（易遗忘/幻觉） |

**经验法则**：要「加知识、可更新、可溯源」→ RAG；要「改说话风格、特定输出格式、小模型提能」→ 微调。两者常结合：RAG 管知识，微调管风格。

## 与本项目的关系
本项目选 RAG 是因为知识（技术文档）会变、要可溯源、且零训练成本。我在评估里发现 faithfulness 偶有波动，优化方向是检索/重排，而非盲目微调。

## 注意
- 微调≠解决幻觉，反而会「记错」；
- RAG 的短板（风格）可面罩 prompt，不一定非要微调。
