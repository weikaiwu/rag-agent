# 上下文工程与记忆管理（Context Engineering）

## 是什么
2025 下半年起，「Context Engineering（上下文工程）」逐渐取代「Prompt Engineering」成为热词。核心思想：LLM 的表现不取决于单个 prompt 写得多好，而取决于**你往上下文窗口里塞了什么、怎么组织**。包括：检索哪些片段、保留哪些历史、注入哪些工具结果、按什么顺序排。

**记忆（Memory）**是上下文工程的一部分，分：
- **短期记忆**：当前会话的对话历史；
- **长期记忆**：跨会话持久化的用户偏好/事实（常存向量库或数据库）；
- **工作记忆**：本轮任务中间结果。

## 为什么重要
上下文太满 → 噪声、超窗口、变贵；太瘦 → 模型缺信息乱答。工程上要在「够用」和「不噪」间平衡。

## 与本项目的关系
- **检索即上下文工程**：多路检索 + 重排 + 动态 TopK 截断，本质就是「精选最相关片段进上下文」；
- **多轮历史**：MongoDB 存对话历史，作为短期记忆；
- **主题确认**：先抽主题再检索，避免无关上下文污染；
- 对应 F4 理念，本项目用「检索质量 + 截断策略」做上下文工程。

## 趋势
2026 年的主要讨论点：如何压缩/摘要历史、如何做长期记忆检索、如何避免上下文污染。
